\subsection{Progettazione database}
\label{subsec:database}
Il diagramma E-R (entità-relazione) mostrato in \hyperref[fig:schema_concettuale]{Figura \ref{fig:schema_concettuale}} espone lo schema concettuale del database.

    \caption{Schema concettuale database.}

Lo schema concettuale è stato ristrutturato per facilitare la definizione dello schema logico ottenendo lo schema equivalente mostrato in \hyperref[fig:schema_concettuale_ristrutturato]{Figura \ref{fig:schema_concettuale_ristrutturato}}.
\begin{figure}[H]
    \centering
    \resizebox{\textwidth}{!}{\includegraphics{Sezioni/ProgettazioneDettaglio/Immagini/schema_concettuale_ristrutturato.png}}
    \caption{Schema concettuale ristrutturato.}
    \label{fig:schema_concettuale_ristrutturato}
\end{figure}
Come si può notare dallo schema ristrutturato:
\begin{enumerate}

    \item Le generalizzazioni \lstinline|Dataset|, \lstinline|Test| e \lstinline|CoppiaChiaveValore| sono state sostituite accorpando le entità figlie nell'entità padre a cui è stato aggiunto un attributo per distinguere le occorrenze.
    Così facendo per le entità \lstinline|Dataset|/\lstinline|Test| viene semplificato il passaggio da temporaneo a salvato.
    Inoltre tutte e tre le generalizzazioni sono composte da entità figlie con pochi attributi propri, quindi il numero di attributi che possono assumere nulli è basso.

    \item La relazione \lstinline|Testset| è stata mantenuta pur essendo derivabile a partire da un occorrenza dell'entità \lstinline|Test| perché riduce il numero di accessi necessari a identificare un testset senza comportare un eccessivo utilizzo di memoria. 
\end{enumerate}

Lo schema ristrutturato è stato utilizzato per produrre lo schema logico del database.
\begin{itemize}
    \item[] \textit{Dataset(\underline{id}, tmp, name, first\_save\_date, last\_save\_date, origin)} \\
    \textit{Dataset.origin $\rightarrow$ Dataset.id}
    
    \item[] \textit{QuestionAnswer(\underline{id}, domanda, risposta, dataset)} \\
    \textit{QuestionAnswer.dataset $\rightarrow$ Dataset.id}
    
    \item[] \textit{Llm(\underline{id}, name, url, key\_response, key\_request, save\_date)}
    
    \item[] \textit{KeyValuePair(\underline{id}, is\_header, key, value, llm)} \\
    \textit{KeyValuePair.llm $\rightarrow$ Llm.id}

    \item[] \textit{Test(\underline{id}, dataset, llm, tmp, name, execution\_date)} \\
    \textit{Test.dataset $\rightarrow$ Dataset.id} \\
    \textit{Test.llm $\rightarrow$ Llm.id}
    
    \item[] \textit{TestResult(\underline{test}, \underline{qa}, is\_correct, similarity\_score, obtained\_answer)} \\
    \textit{TestResult.test $\rightarrow$ Test.id} \\
    \textit{TestResult.qa $\rightarrow$ QuestionAnswer.id}
\end{itemize}
Di seguito vengono analizzate singolarmente le relazioni definite nello schema logico indicando il dominio degli attributi ed eventuali vincoli aggiuntivi.

\subsubsection{Dataset}
\begin{itemize}
    \item \textit{id}: UUID che identifica univocamente un dataset;
    \item \textit{tmp}: valore booleano che indica se il dataset è temporaneo o è stato salvato; non può assumere valore nullo;
    \item \textit{name}: stringa che identifica univocamente il dataset. Se il dataset è temporaneo, deve assumere valore nullo;
    \item \textit{first\_save\_date}: timestamp di creazione del dataset. Se il dataset è temporaneo, deve assumere valore nullo;
    \item \textit{last\_save\_date}: timestamp di ultima modifica del dataset. Se il dataset è temporaneo, deve assumere valore nullo;
    \item \textit{origin}: riferimento (UUID) usato nei dataset temporanei per risalire al dataset originario salvato che modificano.
\end{itemize}

\subsubsection{QuestionAnswer}
\begin{itemize}
    \item \textit{id}: UUID che identifica univocamente un elemento;
    \item \textit{domanda}: stringa che rappresenta la domanda da porre all'LLM da testare;
    \item \textit{risposta}: stringa che rappresenta la risposta attesa alla domanda;
    \item \textit{dataset}: riferimento (UUID) al dataset a cui appartiene l'elemento.
\end{itemize}
\textit{domanda} e \textit{risposta} non possono entrambe assumere valori nulli.

\subsubsection{Llm}
\begin{itemize}
    \item \textit{id}: UUID che identifica univocamente un LLM registrato;
    \item \textit{name}: stringa che identifica univocamente l'LLM; non può assumere valore nullo;
    \item \textit{url}: stringa che rappresenta l'URL da utilizzare per interagire con l'LLM da testare; non può assumere valore nullo;
    \item \textit{key\_request}: chiave da utilizzare per passare all'LLM da testare la domanda relativa a un elemento; non può assumere valore nullo;
    \item \textit{key\_response}: chiave da utilizzare per estrarre la risposta data dall'LLM da testare; non può assumere valore nullo;
    \item \textit{save\_date}: data in cui l'LLM è stato registrato nel sistema; non può assumere valore nullo.
\end{itemize}

\subsubsection{KeyValuePair}
\begin{itemize}
    \item \textit{id}: UUID che identifica univocamente una coppia chiave-valore;
    \item \textit{llm}: UUID dell'LLM per cui è necessario utilizzare le coppie chiave-valore aggiuntive;
    \item \textit{key}: stringa che rappresenta la chiave; non può assumere valore nullo e deve essere univoca;
    \item \textit{value}: stringa che rappresenta il valore; non può assumere valore nullo;
    \item \textit{is\_header}: valore booleano che indica se la coppia chiave-valore deve essere aggiunta all'header o al body delle richieste HTTP da porre all'LLM.
\end{itemize}

\subsubsection{Test}
\begin{itemize}
    \item \textit{id}: UUID che identifica univocamente un test;
    \item \textit{tmp}: valore booleano che indica se il test è temporaneo o salvato; non può assumere valore nullo;
    \item \textit{name}: stringa che identifica univocamente il test; se il test è temporaneo, deve assumere valore nullo;
    \item \textit{execution\_date}: timestamp dell'esecuzione del test; non può assumere valore nullo;
    \item \textit{llm}: UUID del modello LLM da testare, riferimento a \textit{Llm.id};
    \item \textit{dataset}: UUID del dataset utilizzato come test set, riferimento a \textit{Dataset.id}.
\end{itemize}

\subsubsection{TestResult}
\begin{itemize}
    \item \textit{test}: UUID che identifica il test a cui appartiene il risultato; riferimento a \textit{Test.id};
    \item \textit{qa}: UUID che identifica l'elemento (QuestionAnswer) relativo al risultato; riferimento a \textit{QuestionAnswer.id};
    \item \textit{is\_correct}: valore booleano che indica se la risposta ottenuta dall'LLM è stata valutata come corretta; non può assumere valore nullo;
    \item \textit{similarity\_score}: valore numerico (reale) tra 0 e 1 che rappresenta il grado di similarità tra la risposta attesa e quella ottenuta dall'LLM; non può assumere valore nullo;
    \item \textit{obtained\_answer}: stringa che rappresenta la risposta ottenuta dall'LLM alla domanda associata.
\end{itemize}
