\subsection{Descrizione delle classi}

La seguente sezione descrive le classi utilizzate per la gestione dei \textit{Dataset} nel \textit{back-end}.
Vengono descritti gli attributi e i metodi appartenenti a ciascuna classe, le interfacce che sono state implementate e le dipendenze tra le classi del sistema.
Le descrizioni sono suddivise in due sezioni:
\begin{itemize}
    \item \textbf{incoming}: classi che permettono ai livelli esterni di invocare operazioni di business, vengono fornite delle interfacce chiare per l'implementazione dei casi d'uso definiti.
    \item \textbf{outcoming}: classi che permettono l'interazione con servizi esterni, vengono fornite delle interfacce che permettono di realizzare operazioni tecniche mantenendo il dominio indipendente da tacnologie specifiche.
\end{itemize}
Le seguenti sezioni contengono la descrizione di \textit{ports} e \textit{adapters} implementati.

\subsection{Incoming}
\subsubsection{Ports}
\paragraph{DatasetUseCase} 
\begin{itemize}
    \item \textbf{Descrizione}: definisce il contratto per i casi d'uso relativi alla gestione dei dataset;
    \item \textbf{Operazioni}:
    \begin{itemize}
        \item Creazione di un nuovo dataset;
        \item Eliminazione di un dataset;
        \item Aggiornamento dei metadati di un dataset;
        \item Recupero della lista di dataset salvati nel sistema.
    \end{itemize}
    \item \textbf{Implementazione}: i dettagli dell'implementazione sono riportati nella classe concreta.
\end{itemize} 
\subsubsection{Adapters}
\paragraph{DatasetService}
\begin{itemize}
    \item \textbf{Descrizione}: è responsabile della gestione dei dataset;
    \item \textbf{Interfaccia implementata}: DatasetUseCase;
    \item \textbf{Attributi}: \lstinline|_dataset_repo|: istanza della classe \lstinline|DatasetRepository| utilizzata per gestire i dataset nel sistema;
    \item \textbf{Metodi}:
    \begin{itemize}
        \item \lstinline|__init__(self, dataset_repo: DatasetRepository)|: costruttore della classe;
        \item \lstinline|+ create(self, name: str)|: crea un nuovo dataset con il nome fornito.
        Se è già presente un dataset con lo stesso nome del sistema viene alzata un'eccezione di tipo \lstinline|DuplicateNameDatasetError(name)|,
        se ci sono problemi con la creazione del dataset da parte di \lstinline|_dataset_repo| viene alzata un'eccezione di tipo \lstinline|PersistenceError|,
        se l'operazione ha buon fine viene restituito il dataset creato.
        \item \lstinline|+ delete(self, id: UUID)|: elimina il dataset con l'id fornito.
        Se \lstinline|_dataset_repo| non riesce a ottenere il dataset con l'id fornito viene alzata un'eccezione di tipo \lstinline|DatasetNonExsistentError(id)|,
        se ci sono problemi con l'eliminazione del dataset da parte di \lstinline|_dataset_repo| viene alzata un'eccezione di tipo \lstinline|PersistenceError|,
        se l'operazione ha buon fine viene restituito l'id del dataset eliminato.
        \item \lstinline|+ update(self, dataset: Dataset)|: viene rinominato il dataset con i dati ricevuti da \lstinline|dataset|.
        Se \lstinline|_dataset_repo| non riesce a ottenere il dataset tramite id viene alzata un'eccezione di tipo \lstinline|DatasetNonExsistentError(id)|,
        se ci sono problemi con l'aggiornamento del dataset da parte di \lstinline|_dataset_repo| viene alzata un'eccezione di tipo \lstinline|PersistenceError|,
        se l'operazione ha buon fine viene restituito il dataset aggiornato.
        \item \lstinline|+ get_all(self)|: si ottengono tutti i dataset salvati nel sistema.
        Se ci sono problemi con l'ottenimento dei dati da parte di \lstinline|_dataset_repo| viene alzata un'eccezione di tipo \lstinline|PersistenceError|,
        se l'operazione ha buon fine viene restituita una lista contenente tutti i dataset salvati.
        
    \end{itemize}
    \item \textbf{Dipendenze}: DatasetRepository;
\end{itemize}

\subsection{Outcoming}
\subsubsection{Ports}
\paragraph{DatasetRepository}
\begin{itemize}
    \item \textbf{Descrizione}: definisce un contratto per la gestione dei dataset all'interno del sistema;
    \item \textbf{Operazioni}:
    \begin{itemize}
        \item Creazione di un nuovo dataset;
        \item Eliminazione di un dataset;
        \item Aggiornamento dei metadati di un dataset;
        \item Recupero della lista di dataset salvati nel sistema;
        \item Recupero di un dataset tramite il suo id;
        \item Recupero di un dataset tramite il suo nome.
    \end{itemize}
    \item \textbf{Implementazione}: i dettagli dell'implementazione sono riportati nella classe concreta.
\end{itemize}

\subsubsection{Adapters}
\paragraph{SqlAlchemyDatasetAdapter}
\begin{itemize}
    \item \textbf{Descrizione}: interagisce con un database utilizzando \textit{SqlAlchemy} per la gestione dei dataset;
    \item \textbf{Interfaccia implementata}: DatasetRepository;
    \item \textbf{Attributi}: \lstinline|_session|: istanza della classe \lstinline|Session|, creata tramite la factory \lstinline|session_factory|, utilizzata per eseguire operazioni di lettura e scrittura sul database attraverso SQLAlchemy;
    \item \textbf{Metodi}:
    \begin{itemize}
        \item \lstinline|__init__(self, session_factory: Callable[[], Session])|: costruttore della classe;
        \item \lstinline|+ create(self, dataset: Dataset)|: salva il dataset fornito all'interno del database.
        A partire dal \lstinline|dataset|, tramite \lstinline|DatasetSqlAlchemyMapper| viene convertito l'oggetto di dominio \lstinline|Dataset| in un oggetto ORM \lstinline|DatasetSqlAlchemyModel|, utilizzato in seguito per il salvataggio del dataset nel database.
        Se l'operazione ha buon fine viene restituito il dataset creato, altrimenti viene restituito \lstinline|None|.
        \item \lstinline|+ delete(self, id: UUID)|: elimina il dataset con l'id fornito.
        Tramite \lstinline|DatasetSqlAlchemyModel| viene eliminato nel database il dataset che ha come id l'id ottenuto.
        Se l'operazione ha buon fine viene restituito l'id del dataset eliminato, altrimenti viene restituito \lstinline|None|.
        \item \lstinline|+ update(self, dataset: Dataset)|: viene rinominato nel database il dataset.
        Tramite \lstinline|DatasetSqlAlchemyModel| viene rinominato il dataset con il nuovo nome ottenuto da \lstinline|dataset|.
        Se l'operazione ha buon fine viene restituito il dataset rinominato, altrimenti viene restituito \lstinline|None|.
        \item \lstinline|+ get_all(self)|: si ottengono tutti i dataset salvati nel database.
        Tramite \lstinline|DatasetSqlAlchemyMapper| e \lstinline|DatasetSqlAlchemyModel| si ottiene la lista completa di tutti i dataset salvati nel database.
        Se l'operazione ha buon fine viene restituita la lista dei dataset, altrimenti viene restituito \lstinline|None|.
        \item \lstinline|+ find_by_name(self, name: str)|: si ottiene il dataset salvato con il nome fornito.
        Tramite \lstinline|DatasetSqlAlchemyMapper| e \lstinline|DatasetSqlAlchemyModel| si ottiene il dataset salvato nel database che ha come campo nome \lstinline|name|.
        Se l'operazione ha buon fine viene restituito il dataset ottenuto, altrimento viene restituito \lstinline|None|.
        \item \lstinline|+ get_by_id(self, id: UUID)|: si ottiene il dataset salvato con l'id fornito.
        Tramite \lstinline|DatasetSqlAlchemyMapper| e \lstinline|DatasetSqlAlchemyModel| si ottiene il dataset salvato nel database che ha come campo id l'\lstinline|id| ricevuto. 
        Se l'operazione ha buon fine viene restituito il dataset ottenuto, altrimento viene restituito \lstinline|None|.
    \end{itemize}
    \item \textbf{Dipendenze}: DatasetRepository;
\end{itemize}

\subsection{Design Pattern}
Nella seguente sezione vengono descritti i \textit{design pattern} utilizzati, indicando le motivazioni per cui sono stati utilizzati e in quali parti di codice.

\subsubsection{Dependency Injection}
\begin{itemize}
    \item \textbf{Descrizione}: La Dependency Injection (DI) è un \textit{design pattern} che facilita la gestione delle dipendenze tra componenti di un'applicazione, rendendole più flessibili, testabili e manutenibili.
    È una tecnica per fornire oggetti (dipendenze) a una classe dall’esterno, piuttosto che crearli al suo interno, l’oggetto riceve (viene "iniettato" con) le dipendenze di cui ha bisogno.
    L'obiettivo è quello di separare la creazione delle dipendenze dal loro utilizzo, rispettando il principio Inversion of Control (IoC): non è più l’oggetto a controllare come ottenere le sue dipendenze, ma qualcun altro gliele fornisce.
    \item \textbf{Utilizzo}: 
    \begin{itemize}
        \item \textbf{backend}: nel backend è stato utilizzato il \glossario{framework} \textit{Dependency Injector}.
        Questo \glossario{framework} fornisce un \textit{container} esplicito delle dipendenze, che può essere configurato per creare, gestire e risolvere oggetti e relazioni tra oggetti in maniera centralizzata.
        È stato definito un contenitore delle dipendenze, una classe centrale che si occupa di dichiarare e configurare tutti i servizi e componenti di cui l’applicazione ha bisogno.
        All'interno di questo contenitore sono stati specificati diversi provider, ognuno con un ruolo preciso: ad esempio, uno per leggere i parametri di configurazione esterni, uno per istanziare l’engine di connessione al database in modalità singleton (quindi condiviso), e altri per la creazione del gestore delle sessioni e dei servizi dell’applicazione.
        Nelle \textit{route} di \textit{Flask} realizzate, grazie al decoratore \lstinline|@Inject|, viene fornita automaticamente la dipendenza \lstinline|DatasetUseCase| (interfaccia implementata da \lstinline|DatasetService|),
        \lstinline|Provide[AppContainer.dataset\_service]| fornisce l'oggetto \lstinline|dataset\_service| che è stato registrato nel contenitore.
        In questo modo, non viene istanziato manualmente \lstinline|DatasetUseCase| ma lo si riceve dal contenitore già configurato.
        \item \textbf{frontend}: nel frontend è stata utilizzata la gestione della dependency injection nativa del \glossario{framework} \textit{Angular}.
        Il \lstinline|DatasetService| definito in \textit{Angular} è stato annotato con \lstinline|@Injectable| e definito come \textit{Singleton} tramite \lstinline|provideIn: root|, in questo modo può essere iniettato automaticamente nei componenti o in altri servizi. 
        Questo ha permesso una gestione centralizzata della logica di business lato client e un’integrazione efficace con l’\glossario{API REST} del backend. 
    \end{itemize}
\end{itemize}

\subsubsection{Port e Adapter}
\begin{itemize}
    \item \textbf{Descrizione}: \textit{Port e Adapter}, noto anche come \textit{Hexagonal Architecture}, è un design pattern architetturale 
    che realizza la separazione tra il \textit{core} e le interfacce di input e otuput dell'applicazione.
    Questo pattern permette la separazione delle responsabilità mantenendo il \textit{core} isolato, agevolando la manutenzione del sistema e la fase di testing;
    \item \textbf{Utilizzo}: vi è la separazione in:
    \begin{itemize}
        \item \textbf{incoming}: la porta \lstinline|DatasetUseCase| rappresenta le operazioni (gli \textit{use case}) che l'applicazione espone al mondo esterno, consiste in un interfaccia che fornisce i metodi necessari per gestire i dati in ingresso ed è implementata dall'adapter \lstinline|DatasetService|.
        \item \textbf{outcoming}: la porta \lstinline|DatasetRepository| rappresenta i punti attraverso cui la logica applicativa delega operazioni a sistemi esterni, viene realizzata tramite un'interfaccia ed è implementata dall'adapter \lstinline|SqlAlchemyDatasetAdapter|.
        In questo modo l’applicazione rimane indipendente dai dettagli tecnici esterni, rendendo il sistema più  testabile e facilmente manutenibile.
    \end{itemize}
\end{itemize}

\subsubsection{DTO (Data Transfer Object)}
\label{subsubsec:DTO}
Qui vengono descritti i DTO utilizzati per il trasferimento dei dati tra gli strati dell'applicazione.
I DTO sono dei contenitori semplici di dati non contenenti logica di business, progettati per aggregare dati e facilitare la comunicazione tra i vari livelli dell'applicazione.
\begin{itemize}
    \item \textbf{DatasetCreateDto}:\\
    DTO utilizzato per rappresentare i dati necessari alla creazione di un nuovo dataset nel sistema.
    \begin{itemize}
        \item \texttt{name: str}, nome del dataset da creare.
    \end{itemize}

    \item \textbf{DatasetUpdateDto}:\\
    DTO utilizzato per rinominare un dataset esistente nel sistema.
    \begin{itemize}
        \item \texttt{id: UUID}, identificatore univoco del dataset da aggiornare;
        \item \texttt{name: str}, nuovo nome da assegnare al dataset.
    \end{itemize}

    \item \textbf{DatasetResponseDto}:\\
    DTO utilizzato per rappresentare un singolo dataset restituito dal sistema.
    \begin{itemize}
        \item \texttt{id: UUID}, identificatore univoco del dataset;
        \item \texttt{name: str}, nome del dataset;
        \item \texttt{creation\_date: date}, data di creazione del dataset.
    \end{itemize}

    \item \textbf{DatasetResponseListDto}:\\
    DTO utilizzato per rappresentare una lista di dataset presenti nel sistema.
    \begin{itemize}
        \item \texttt{datasets: DatasetResponseDto[*]}, elenco di oggetti \texttt{DatasetResponseDto} che rappresentano i dataset disponibili.
    \end{itemize}
\end{itemize}
