\subsection{Processo di miglioramento} 
\label{subsec:miglioramento}

Questo documento definisce le procedure operative per l'analisi, la valutazione e il miglioramento continuo del processo di sviluppo software, al fine di garantire elevati standard di qualità e l'efficienza dei processi.

\subsubsection{Scopo}
Definire in maniera operativa le linee guida e le procedure per:
\begin{itemize}
    \item Stabilire obiettivi chiari di qualità e performance.
    \item Standardizzare il ciclo di sviluppo e manutenzione.
    \item Favorire il miglioramento continuo e la riduzione dei rischi operativi.
\end{itemize}

\subsubsection{Attività}
Le attività operative da eseguire sono:
\begin{enumerate}
    \item \textbf{Raccolta Dati:}
    \begin{itemize}
        \item Identificare e registrare metriche di qualità.
        \item Utilizzare strumenti automatici per il monitoraggio.
        \item Archiviazione.
    \end{itemize}
    \item \textbf{Analisi e Identificazione delle Criticità:}
    \begin{itemize}
        \item Confrontare i dati raccolti con benchmark (strumenti automatici) e standard di settore (valori limite).
        \item Individuare le criticità operative. Aree con valori al limite soglia possono essere provocate da un'applicazione non ottimale dell'attività di uno o più processi.
    \end{itemize}
    \item \textbf{Definizione delle Azioni Correttive:}
    \begin{itemize}
        \item Pianificare interventi specifici per ogni criticità identificata.
        \item Documentare le cause e le soluzioni proposte.
    \end{itemize}
\end{enumerate}

\subsubsection{Raccolta Dati}
Le procedure per la raccolta dei dati sono le seguenti:
\begin{enumerate}
    \item \textbf{Identificazione delle Metriche:}
    \begin{itemize}
        \item Selezionare indicatori chiave di performance (KPI) e metriche di qualità (es. tasso di difetti, copertura dei test, tempi di risposta).
        \item Definire le unità di misura e le modalità di rilevazione.
    \end{itemize}
    \item \textbf{Implementazione degli Strumenti di Monitoraggio:}
    \begin{itemize}
        \item Configurare sistemi di monitoraggio (es. script automatici, SonarQube, Prometheus).
        \item Integrare i tool all’interno del ciclo di sviluppo per una raccolta dati continua.
    \end{itemize}
    \item \textbf{Archiviazione:}
    \begin{itemize}
        \item Stabilire una struttura di archiviazione (piano di qualifica) per conservare i dati raccolti.
        \item Eseguire controlli periodici per verificare la coerenza e l’accuratezza dei dati.
    \end{itemize}
\end{enumerate}

\subsubsection{Analisi e Identificazione delle Criticità}
Le procedure per analizzare i dati e identificare le criticità sono le seguenti:
\begin{enumerate}
    \item \textbf{Confrontare i dati raccolti:}
    \begin{itemize}
        \item Creare grafici che rappresentino i dati precedentemente raccolti.
        \item definire range limite per definire andamenti positivi e negativi.
    \end{itemize}
    \item \textbf{Individuazione delle Criticità:}
    \begin{itemize}
        \item Individuare se sono presenti valori che si discostano negativamente dal limite soglia.
        \item Individuare consistenza dello scostamento dalla soglia in quante più metriche possibili a pari iterazione.
    \end{itemize}
\end{enumerate}

\subsubsection{Definizione delle Azioni Correttive}
Le procedure per definire e implementare le azioni correttive sono le seguenti:
\begin{enumerate}
    \item \textbf{Analisi delle Cause:}
    \begin{itemize}
        \item Utilizzare tecniche strutturate (es. i 5 Perché, diagramma di Ishikawa) per identificare le cause radice delle criticità.
        \item Documentare dettagliatamente ogni causa individuata.
    \end{itemize}
    \item \textbf{Pianificazione degli Interventi:}
    \begin{itemize}
        \item Redigere un piano d’azione che definisca obiettivi, attività operative, responsabilità e scadenze per ciascun intervento.
        \item Prioritizzare gli interventi in base all’urgenza e all’impatto sul processo.
    \end{itemize}
    \item \textbf{Documentazione:}
    \begin{itemize}
        \item Documentare ogni intervento di correzione a fine di ogni iterazione.
    \end{itemize}
\end{enumerate}

\subsubsection{Strumenti}
\begin{itemize}
    \item SonarQube per il monitoraggio e l’analisi approfondita della qualità del codice
    \item SonarQube per l’integrazione continua e l’automatizzazione del controllo qualità
    \item LaTeX per la rappresentazione grafica e formale delle metriche
    \item GitHub per la gestione centralizzata del codice sorgente, la documentazione e la risoluzione delle anomalie
    \item Discord per la discussione e la risoluzione di criticità di natura strategica
\end{itemize}
